# Decision — World-class authoring product benchmark

**Date:** 2026-09-09  
**Status:** ACCEPTED / OWNER DIRECTION  
**Applies to:** BOOK OS product UX, desktop interaction design, author workflow and commodity authoring capabilities

## Owner direction

BOOK OS must not reinvent solved authoring/product UX from first principles when mature world-class products already demonstrate a stronger pattern.

Working rule:

> **The bicycle is already invented: collect the strongest proven mechanisms from the best products and make the combined BOOK OS experience better.**

## Consequences

1. For commodity authoring UX, Central Brain must benchmark current leading products before defining a new interaction pattern.
2. Prefer a proven world-class pattern unless BOOK OS has a concrete reason to diverge.
3. Divergence must improve a BOOK OS-specific need such as authority, evidence integrity, long-form coherence, series overlap, author voice, model routing or reproducibility — not merely make the interface different.
4. The default author surface must expose the current creative/editorial task, not internal implementation concepts.
5. Advanced diagnostics, provenance, model plumbing, API credentials and developer-facing controls must use progressive disclosure and stay out of the primary author flow unless directly required by the current action.
6. World-class simplicity is an acceptance requirement. If a commodity task is materially harder to understand in BOOK OS than in mature benchmark products, treat that as a product defect.
7. BOOK OS should combine the strongest mechanisms across tools rather than clone one competitor wholesale.
